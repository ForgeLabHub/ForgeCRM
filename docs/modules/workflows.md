# Модуль: Workflow (автоматизация)

## 1. Назначение и границы
Автоматизация реакций на события: триггеры (событие, расписание, ручной запуск),
шаги, условия, журнал выполнения. Не делает: не исполняет произвольный код —
только объявленные действия.

## 2. Сценарии использования
- «Сделка перешла в стадию → создать задачу и уведомить».
- «Расписание → найти просроченные тикеты → эскалировать».
- Ручной запуск с параметрами и просмотр журнала шагов.
- Отказ: неизвестный триггер/шаг отвергается на сохранении, а не в рантайме.

## 3. Контракт
`/api/v1/workflows/*` (CRUD, шаблоны, импорт/экспорт, ручной запуск).
Определение workflow — декларативная структура (`definition.go`), выражения —
`expression.go` (без произвольного исполнения). События и журнал:
`workflow_runs`, `workflow_step_runs`, `workflow_run_events`.

## 4. Данные
Владеет: `workflows`, `workflow_runs`, `workflow_step_runs`, `workflow_run_events`,
`approvals`. Действия над CRM выполняются через контракт `crm`.
Миграции: `0012_workflows`, `0013_seed_workflow_permissions`.

## 5. Права
Права домена `workflows.*`; действия шагов дополнительно проверяются правами
целевой сущности. Ручной запуск требует отдельного права.

## 6. Зависимости
Исходящие: `crm`, `events`, `outbox`, `jobs`, `audit`, `notify` (через контракт).
Входящие: `api`, `worker`.
Внешние системы — только через интеграционные адаптеры.

## 7. Конфигурация
Собственных переменных нет; расписания хранятся в данных. Зависит от того, что
worker запущен — иначе триггеры по расписанию не срабатывают (см.
[operations/monitoring.md](../operations/monitoring.md)).

## 8. Сборка и отладка
Исполнение — в worker (`make build-worker`). Проверки:

```bash
cd backend && go test ./internal/workflow/... -v
```

## 9. Тесты
`internal/workflow/definition_test.go`, `templates_test.go`;
`internal/testsupport/workflow_engine_test.go`, `workflow_templates_test.go`
(исполнение против реальной БД). Frontend: `WorkflowEditor.test.tsx`.

## 10. Наблюдаемость и ошибки
История прогонов и шагов доступна в API и UI; ошибки шага не теряются, а фиксируются
в `workflow_step_runs`. Ошибки: `invalid_definition`, `step_failed`, `denied`.

## 11. Ограничения и готовность
- Нет циклов и длительных ожиданий внутри шага.
- Шаблоны — из каталога, произвольные «скрипты» не поддерживаются осознанно.
- Готовность: неизвестные конструкции отвергаются при сохранении; журнал позволяет
  восстановить ход выполнения; импорт/экспорт не ломает существующие запуски.
