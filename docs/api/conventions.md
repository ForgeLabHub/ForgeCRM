# Соглашения API

Спецификация: [`openapi.json`](openapi.json) — **генерируется** из живого роутера
(`make openapi`), проверяется в CI (`make openapi-check`). 147 путей, OpenAPI 3.1.

## Базовые правила

| Правило | Деталь |
| --- | --- |
| Префикс | `/api/v1`; аутентификация — `/api/v1/auth` |
| Формат | JSON, `Content-Type: application/json` |
| Идентификаторы | UUID v4 (кроме внутренних числовых последовательностей) |
| Время | RFC 3339, UTC (`2026-10-29T12:00:00Z`) |
| Деньги | целые минорные единицы + код валюты; `float` отсутствует |
| Имена полей | `snake_case` |
| Отсутствие значения | `null` отличается от «поля нет» |

## Аутентификация и авторизация

- Сессия — HttpOnly cookie, CSRF-заголовок обязателен для небезопасных методов
  (`FORGECRM_CSRF_HEADER`), SameSite и `Secure` настраиваются окружением.
- Второй фактор (TOTP) и step-up для деструктивных действий.
- Права — RBAC: каждый маршрут объявляет требуемое право; отказ — `403`, а не
  «пустой список». Полный каталог — [security/permissions.md](../security/permissions.md).
- OIDC — опциональная альтернатива локальному входу.

## Списки, пагинация, поиск

Пагинация — по смещению: `?limit=&offset=`. Ответ содержит `items`, `total`,
`limit` и `offset`; `total` — это число записей, удовлетворяющих фильтру, а не
размер страницы, поэтому клиент может построить постраничную навигацию и показать
общее количество. Предел `limit` ограничен сервером (`MaxPageSize`); превышение не
ошибка, а усечение до максимума — и это отражено в спецификации.

Курсорной пагинации нет намеренно. Она устойчивее к вставкам между страницами,
но требует стабильного ключа сортировки на каждом списке, а списки здесь
сортируются по разным колонкам. Пока такого ключа нет, смещение честнее: клиент
видит `total` и может повторить запрос, а не получить молча сдвинутую страницу под
видом курсора.

## Идемпотентность

Изменяющие операции принимают заголовок `Idempotency-Key`. Повтор с тем же
ключом возвращает исходный результат и помечается заголовком
`Idempotent-Replay: true`, а не создаёт дубль; состояние хранится в
`idempotency_keys`. Ключ привязан к вызывающему и к операции (организация,
пользователь, метод, путь), поэтому один ключ не может столкнуться с ключом
другого пользователя или другой операции. Пока первый запрос ещё выполняется,
параллельный запрос с тем же ключом получает `409` с `Retry-After`, а не
выполняется дважды. Неуспешный запрос освобождает ключ, чтобы исправленный повтор
с тем же ключом прошёл.

Заголовок объявлен в спецификации на каждой изменяющей операции, у которой есть
вызывающий (аутентифицированные маршруты и MCP). На анонимных маршрутах он не
объявлен намеренно: ключ привязывается к разрешённому вызывающему, а у запроса
без сессии такого вызывающего нет.

Ответ, который обработчик помечает `Cache-Control: no-store`, не сохраняется в
`idempotency_keys`. Так помечаются ответы, выдающие одноразовый секрет — семя
второго фактора, токен MCP-доступа, код привязки Telegram. Иначе секрет остался
бы в таблице в открытом виде и был бы повторён на запрос с тем же ключом, а
обещание «показывается один раз» перестало бы выполняться.

## Ошибки

Единая схема — [errors.md](errors.md). Кратко: HTTP-код + `code` (машиночитаемый)
+ `message` (человеческий) + опциональные `details` и `request_id`.

## Ограничения

- Rate limit: `FORGECRM_RATE_LIMIT_PER_MIN` (по умолчанию 300), вход в систему —
  отдельный лимит; при превышении `429` + `Retry-After`.
- Размер тела запроса и загрузок ограничен конфигурацией импорта.
- Версионирование: ломающие изменения — только в `/api/v2`; в рамках `v1`
  допустимы аддитивные изменения.

## Как менять API

1. Изменить маршрут или схему в коде.
2. `make openapi` — перегенерировать спецификацию.
3. Обновить страницу/клиент во `frontend/src/api`.
4. Прогнать `make verify` (в том числе `openapi-check`) и E2E.
5. Добавить строку в [verification/matrix.md](../verification/matrix.md), если
   появилось новое утверждение, которое надо доказывать.
