# Резервное копирование и восстановление

Скрипты: `scripts/backup.sh`, `scripts/restore.sh`, цели `make backup` / `make restore`.

## Что копируется

| Артефакт | Содержимое | Куда |
| --- | --- | --- |
| `forgecrm-db-<STAMP>.dump` | PostgreSQL, custom-format (восстановление `pg_restore`) | каталог из аргумента (по умолчанию `./backups`) |
| `forgecrm-imports-<STAMP>.tar.gz` | том вложений/импорта | рядом с дампом |
| `.sha256` | контрольная сумма дампа | рядом |

Дамп снимается с `--serializable-deferrable`: копия отражает одну точку во
времени, даже если API продолжает обслуживать запросы.

## Процедура

```bash
make backup BACKUP_DIR=./backups       # снять копию
sha256sum -c backups/*.dump.sha256     # проверить целостность
make restore DUMP=backups/forgecrm-db-20260101T000000Z.dump   # восстановить
```

`restore.sh` уничтожает текущее содержимое БД и поэтому требует `--yes-really`;
сначала сверяет контрольную сумму, если она есть.

## Что считается доказательством, а не надеждой

Копия, которую ни разу не восстанавливали, — не резервная копия. Поэтому в CI
выполняется полный цикл **backup → restore → smoke-test** на чистом PostgreSQL
(`.github/workflows/portability.yml`, job `backup-restore`). Проверяется не только
успешный код возврата, но и то, что после восстановления сервис отвечает и данные
читаются.

## Расписание и хранение (рекомендация для эксплуатации)

- Ежедневно — полный дамп, хранить 14 дней.
- Еженедельно — копия в другое место (другой диск/бакет), хранить 8 недель.
- Перед каждой миграцией — внеплановый дамп: откат схемы не автоматизирован.
- Ключ `FORGECRM_SECRET_KEY` хранится **отдельно** от дампа: без него расшифровать
  секреты интеграций из копии невозможно.

## Восстановление после сбоя

1. Остановить API и worker (`make compose-down`), чтобы не принимались записи.
2. Поднять пустой PostgreSQL.
3. Восстановить дамп и том вложений.
4. Применить ожидаемые миграции, если копия старше кода (`make migrate`).
5. Запустить стек, выполнить `make smoke-test`.
6. Сверить количество ключевых записей (`contacts`, `deals`) с ожидаемым.
