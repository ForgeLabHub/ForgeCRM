# Дизайн-система и локализация фронтенда

Этот документ описывает визуальный слой ForgeCRM: токены, темы, локализацию и
оболочку приложения. Он намеренно короткий — единственный источник правды по
значениям это `frontend/src/index.css`, а этот файл объясняет, *почему* устроено
именно так и где что менять.

Библиотеки компонентов нет. Это осознанный выбор: приложение небольшое, а
собственный набор примитивов держит бандл маленьким и делает разметку читаемой.
Плата за это — дисциплина: новые экраны собираются из существующих примитивов, а
не из одноразовых стилей.

## Токены

Все цвета, радиусы, тени и отступы — это CSS-переменные на `:root`. Компонент
никогда не задаёт «магическое» значение цвета напрямую; он ссылается на токен.
Это то, что делает переключение темы одним изменением атрибута, а не проходом по
всем компонентам.

| Группа | Примеры | Назначение |
| --- | --- | --- |
| Поверхности | `--color-bg`, `--color-bg-subtle`, `--color-surface`, `--color-surface-raised` | Фон страницы, фон таблиц, карточки |
| Границы | `--color-border`, `--color-border-strong` | Обычные и акцентные границы полей |
| Текст | `--color-text`, `--color-text-muted`, `--color-text-subtle` | Основной, вторичный, третичный текст |
| Акцент | `--color-accent`, `--color-accent-hover`, `--color-accent-active`, `--color-accent-soft`, `--color-accent-border`, `--color-on-accent` | Действие, выделение, текст на акценте |
| Статусы | `--color-danger*`, `--color-success*`, `--color-warning*` | Ошибка, успех, предупреждение и их мягкие фоны |
| Бренд | `--gradient-brand`, `--gradient-hero` | Логотип и панель входа — и только они |
| Радиусы | `--radius-xs` … `--radius-xl` | Скругления |
| Тени | `--shadow-xs` … `--shadow-lg`, `--ring` | Глубина и фокус-кольцо |
| Отступы | `--space-1` … `--space-7` | Шаг сетки 4px |
| Раскладка | `--sidebar-width`, `--header-height` | Размеры оболочки |

`--color-on-accent` существует потому, что акцент в тёмной теме светлеет: белый
текст на нём упал бы ниже 4.5:1. Токен вместо константы `#fff` — это то, что
сохраняет контраст кнопки в обеих темах.

## Темы

Режимов три: `light`, `dark`, `system`. Выбор хранится в `localStorage` под
ключом `forgecrm.theme` и применяется к `<html>` атрибутом `data-theme`.

Тёмная палитра выбирается двумя путями, и это не избыточность:

1. `:root[data-theme='dark']` — пользователь явно выбрал тёмную тему;
2. `@media (prefers-color-scheme: dark) :root:not([data-theme])` — системная тема,
   пока явного выбора нет.

`:root[data-theme='light']` всегда выигрывает у системной. Именно поэтому
«System» — настоящий третий режим, а не синоним «что скажет ОС»: выбрав Light при
тёмной ОС, пользователь получает светлую тему, а выбрав System — снова следует за
ОС.

Вспышки неправильной темы нет. Её предотвращает маленький inline-скрипт в
`frontend/index.html`, который выполняется до первого кадра и выставляет тот же
атрибут. React-провайдер (`src/theme`) лишь синхронизирует с ним своё состояние
после монтирования; он не устанавливает тему впервые.

Системная тема отслеживается вживую через `matchMedia`, поэтому смена темы ОС
отражается без перезагрузки.

## Локализация

Локализация — это провайдер над двумя плоскими словарями, `src/i18n/en.ts` и
`src/i18n/ru.ts`, а не набор тернарников в компонентах. Тернарники — ровно то,
что порождает смешанные RU/EN экраны, которые эта система заменяет.

- Английский словарь — эталон формы. Русский типизирован против него
  (`const ru: Dictionary`), поэтому пропущенный ключ — ошибка компиляции, а не
  пустая подпись в рантайме.
- Значения намеренно расширены до `string`: с `as const` каждая строка стала бы
  литеральным типом, и русский словарь мог бы содержать только английские слова.
  Расширение сохраняет *набор ключей* точным, позволяя значениям различаться.
- Выбранная локаль хранится в `localStorage` (`forgecrm.locale`) и пишется в
  `<html lang>`, поэтому переносы и скринридеры следуют выбору.
- `t()` возвращается к английскому, а не к сырому ключу: отсутствующий перевод
  должен деградировать до читаемой подписи, а не до `login.submit`.
- `useI18n()` вне провайдера возвращает английский словарь, а не бросает ошибку.
  Локализация — это представление; её потеря не должна ронять экран.

Правило для нового экрана: ни одной строки, видимой пользователю, прямо в
разметке. Всё через `t()`, ключ добавляется в оба словаря.

## Оболочка приложения

`src/components/AppShell.tsx` — это постоянный каркас: боковая навигация, верхняя
панель, область содержимого и командная палитра.

- Навигация сгруппирована по смыслу (Workspace / Data / Platform / Administration),
  а не по префиксу API, поэтому читается как продукт, а не как таблица маршрутов.
- Каждый пункт объявляет нужное разрешение и скрывается без него. Скрытие ссылки —
  это удобство, а не безопасность: сервер проверяет то же разрешение независимо.
- Подписи — это ключи перевода, а не литералы, поэтому смена языка переименовывает
  всю навигацию одним куском.
- Иконки — собственный набор в `src/components/NavIcons.tsx`: одна сетка 24px,
  штрих 1.7px, без шрифта и спрайта. Каждая иконка декоративна (`aria-hidden`),
  доступное имя даёт текст ссылки.
- На узком экране боковая панель превращается в выдвижной ящик с подложкой; он
  закрывается по Escape и по переходу, иначе перекрывал бы открытую страницу.

## Командная палитра

Глобальный поиск (`src/components/GlobalSearch.tsx`) открывается по `Ctrl/⌘ K` и
ищет по записям, которые вызывающему разрешено видеть. Сервер фильтрует результаты
по правам и организации, поэтому пустой результат может означать «нет совпадений»
или «нет прав», и эти два случая намеренно неразличимы в интерфейсе: сообщить, что
запись существует, но скрыта, означало бы выдать её существование.

## Доступность

- Видимый фокус для клавиатуры через `:focus-visible`; кольцо — токен `--ring`.
- Ссылка «Перейти к содержимому» первым элементом оболочки.
- Ошибки формы связаны с полями через `aria-describedby` и объявляются `role="alert"`.
- Фокус переводится на регион ошибки после неудачной отправки формы.
- Контраст текста рассчитан на обе темы; для текста на акценте используется
  `--color-on-accent`, а не белый.
- Уважается `prefers-reduced-motion`: анимации скелетона отключаются.
- Горизонтального переполнения нет ни на 1440px, ни на 390px — это проверяется в
  сквозных тестах.

## Проверки

```bash
cd frontend
npm run typecheck   # набор ключей и типы
npm run lint
npm run test        # компоненты против заглушённого fetch
npm run build
npm run e2e         # реальный браузер против реального API и PostgreSQL
```

Сквозной набор (`frontend/e2e/login.spec.ts`) проверяет то, что модульные тесты с
заглушками пропускают: что переключатели языка и темы действительно работают,
сохраняются между визитами и применяются после входа.
