# Стиль кода

## Общие правила

1. **Читаемость важнее краткости.** Код читают чаще, чем пишут.
2. **Комментарий объясняет «почему», а не «что».** Пересказ кода — шум.
3. **Ошибка обрабатывается или явно игнорируется с причиной.** Молчаливый `_ =` без
   комментария — дефект.
4. **Никакой бизнес-логики в handler'ах** — только валидация входа и вызов сервиса.

## Go

- `gofmt` обязателен (`make fmt-check`); `go vet` без замечаний.
- Ошибки оборачиваются с контекстом: `fmt.Errorf("create deal: %w", err)`.
- `context.Context` — первый аргумент, отмена пробрасывается.
- Пакеты называются по ответственности, а не по типу (`crm`, а не `models`).
- Границы зависимостей — [architecture/dependency-rules.md](../architecture/dependency-rules.md).
- Внешние интерфейсы объявляются у потребителя, а не у реализации, если потребитель
  один.

## TypeScript / React

- Один файл — один маршрут или одна область API.
- Типы API в `src/types/api.ts` отражают `docs/api/openapi.json`.
- Состояния загрузки и ошибки обязательны на каждой странице: «пусто», «грузится»,
  «ошибка» — три разных экрана.
- Права проверяются через `RequirePermission`, но не как замена серверной проверке.

## SQL / миграции

- Только парами `up`/`down`, только вперёд, никогда не править применённое.
- Явные имена индексов и ограничений.
- Деньги — целые числа, валюта отдельной колонкой.

## Документация

- Заголовки в единственном смысле, без «и так далее».
- Ссылки — относительные, проверяются `make docs-check`.
- Числа в документах либо проверяются автоматически, либо сопровождаются датой.

## Коммиты и PR

- Сообщение коммита отвечает на вопрос «что изменится для системы».
- Один PR — одна причина изменения.
- PR не проходит без зелёной матрицы проверок.
