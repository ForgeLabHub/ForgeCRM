# Права доступа и изоляция арендаторов

## Модель

- **Каталог прав** — `internal/rbac/rbac.go`: **103 права** вида `<домен>.<действие>`
  (`deals.read`, `deals.write`, `imports.run`, `webhooks.manage`, …).
- **Системные роли** — 14: `platform_owner`, `platform_admin`, `tenant_admin`,
  `sales_manager`, `sales_representative`, `support_manager`, `support_agent`,
  `analyst`, `data_steward`, `employee`, `executive`, `integration_admin`,
  `security_auditor`, `readonly_auditor`.
- **Права назначаются ролям** (`role_permissions`), роли — пользователям
  (`user_roles`) внутри организации.
- Каталог синхронизирован с миграциями: `0004_rbac_seed`, `0006_seed_webhooks_manage`,
  `0010_seed_agent_permissions`, `0013_seed_workflow_permissions`, `0019_simulation_lab`,
  `0020_forecasting_risk`, `0022_sso_oidc`, `0023_saved_views`, `0025_mcp_credentials`,
  `0027_consent`, `0028_tenant_configuration`. Расхождение ловится unit-тестами.

## Где проверяется

1. **На маршруте.** Каждый маршрут объявляет требуемое право; маршрут без права —
   дефект, а не «открытая ручка». Проверка: `internal/api/contract_test.go`,
   `capabilities_test.go`.
2. **В домене — только как утверждение о данных**, не как замена проверке маршрута.
3. **В UI** — `RequirePermission` прячет элементы, но это удобство, а не защита.

## Изоляция арендаторов

- Каждый запрос получает tenant-контекст до входа в handler.
- Запросы к данным всегда содержат `organization_id` из контекста; значение из тела
  запроса игнорируется.
- Платформенные администраторы работают через отдельные маршруты с явным
  намерением, а не через «выключение фильтра».
- Доказательство: `internal/api/tenant_isolation_test.go`,
  `internal/api/isolation_cases_test.go` — включая попытки доступа по прямому UUID
  чужой записи.

## Правило владения объектом (owner / team)

Изоляции арендатора недостаточно: внутри одной организации запись, которую
пользователь не видит в списке, не должна читаться и изменяться по прямому UUID —
это класс ошибок **BOLA/IDOR**.

- Единое правило живёт в `internal/crm/crm.go` (таблица `objectRules` +
  `objectOwnerPredicateFor`) и применяется одинаково **списком, чтением по id,
  поиском, экспортом и записями** для `accounts`, `contacts`, `leads`, `deals`,
  `tasks`, `tickets`.
- **Экспорт** (`importx.Export`) использует тот же фильтр через
  `crm.ObjectScopeFilter`, поэтому запись, скрытую списком, нельзя выгрузить.
- **Вложенные ресурсы** — комментарии, теги, лента активностей — не имеют
  собственного владельца: решение принимается по родительской записи.
  `ListComments`/`CreateComment`, `ListEntityTags`/`TagEntity` вызывают
  `ensureReadableObject`, а лента активностей (`ListActivities`) фильтруется
  `activityScopeFilter` по достижимым родителям. Вложение не может быть
  «шире» своей родительской записи.
- Вызывающий без «полного» права (архив для CRM-сущностей, назначение для задач и
  тикетов) видит только записи, где `owner_user_id`/`assignee_user_id` — его, либо
  `team_id` входит в его команды.
- Семантика для вызывающего без команды сохраняется как в списках: общие
  CRM-записи считаются доступными на уровне организации, а личные рабочие элементы
  (задачи, тикеты) без команды показывают только свои. Правило не меняет бизнес-
  поведение, а выравнивает по нему чтение по id и записи.
- Команды вызывающего резолвятся единообразно через
  `rbac.Service.TeamIDsForUser` из **всех** построителей принципала — сессии, MCP-
  токена, автора workflow и AI-агента, — поэтому правило нельзя обойти, выбрав
  другой способ аутентификации.
- Доказательство: `internal/testsupport/object_authz_test.go` (same-tenant и
  cross-tenant, паритет «чтение по id против списка», поиск, отказ в записи,
  доступ владельца).

## Как добавить право

1. Добавить код в `rbac.go`.
2. Добавить миграцию-seed с назначением ролям (нумерованная, вперёд).
3. Объявить право на маршруте.
4. Добавить тест: «пользователь без права получает 403».
5. Обновить эту страницу и, при необходимости, `docs/api/openapi.json` (`make openapi`).

## Проверка после изменений

```bash
make test-unit          # каталог прав и согласованность
make test-integration   # изоляция арендаторов против реальной БД
```
