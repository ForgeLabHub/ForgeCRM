# Модель угроз

## Что защищаем

| Актив | Почему важен |
| --- | --- |
| Данные арендаторов | смешение данных разных организаций — репутационная и юридическая катастрофа |
| Учётные данные и сессии | захват сессии равен захвату арендатора |
| Секреты интеграций | SMTP, S3, AI-ключи, токены вебхуков |
| Аудит | без него невозможно расследование |
| Доступность | CRM часто критичен для продаж |

## Акторы

1. Внешний атакующий без учётной записи.
2. Легитимный пользователь, пытающийся выйти за свои права.
3. Скомпрометированная учётная запись.
4. Вредоносный файл импорта (архив, CSV с формулами, XLSX).
5. Враждебный внешний сервис, на который мы шлём вебхуки.
6. Ошибка в конфигурации эксплуатации.

## Угрозы и меры

| Угроза | Мера | Где проверяется |
| --- | --- | --- |
| Подбор пароля | блокировка после `FORGECRM_LOCKOUT_THRESHOLD`, отдельный rate limit входа, журнал `login_attempts` | `internal/authn/lockout_integration_test.go` |
| Захват сессии | HttpOnly + SameSite + Secure cookie, ротация сессии, step-up для деструктивных действий | `internal/api/session_sharing_test.go`, `step_up_handlers.go` |
| Обход CSRF | обязательный CSRF-заголовок для небезопасных методов | `internal/api/*_test.go` |
| Межарендаторская утечка | tenant-контекст в запросе, обязательный `organization_id`, тесты изоляции | `tenant_isolation_test.go`, `isolation_cases_test.go` |
| Обход RBAC | право объявлено на маршруте, тест на «каждый маршрут объявляет право» | `capabilities_test.go`, `contract_test.go` |
| Zip-bomb / path traversal в импорте | лимиты глубины, количества файлов, распакованного объёма и коэффициента сжатия | `internal/importx/safe/*_test.go` |
| CSV-инъекция при экспорте | экранирование формул в ячейках | тесты экспорта |
| SSRF через вебхуки/интеграции | блокировка приватных диапазонов, проверка адреса после резолва | `internal/integrations/ssrf_test.go` |
| Утечка секретов в репозиторий | `.gitleaks.toml` и сканирование в CI | job `security` |
| Утечка секретов в логи | секреты шифруются (`internal/secrets`), значения не логируются | ревью + тесты |
| Враждебный AI-ответ | инструменты модели проходят RBAC, деструктивные — через подтверждение человеком | `internal/agent/*_test.go` |
| Отказ в обслуживании | rate limit, ограничения размеров тела и загрузок | `ratelimit_test.go` |
| Компрометация зависимости | `govulncheck`, `gosec`, `pip-audit`-аналог для Go-модулей | job `security` |

## Границы доверия

- **Доверенная зона:** контейнеры API/worker и PostgreSQL в одной сети Compose.
- **Недоверенное:** всё, что приходит по HTTP; все файлы импорта; все ответы
  внешних сервисов; содержимое, сгенерированное моделью.
- **Особый случай:** доверенный прокси. `FORGECRM_TRUSTED_PROXIES` определяет, чьим
  `X-Forwarded-For` можно верить. Ошибка здесь превращает лимиты и аудит в фикцию.

## Что осознанно не защищено

- **Доступ администратора БД.** Обладатель суперпользователя PostgreSQL видит данные
  всех арендаторов. Изоляция арендаторов — прикладная гарантия, не шифрование.
- **Шифрование данных на диске** — ответственность инфраструктуры.
- **Вредоносный администратор арендатора** может испортить свои данные: аудит
  фиксирует, но не предотвращает.
