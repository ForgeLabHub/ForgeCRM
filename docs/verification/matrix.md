# Матрица проверок

Каждое утверждение о переносимости подкреплено командой и заданием CI. Строка без
команды — обещание, а не гарантия.

| Проверка | Что доказывает | Команда | CI |
| --- | --- | --- | --- |
| Сборка на чистом Linux-runner | нет зависимости от машины автора | `make build` | `ci.yml` → `backend`, `frontend` |
| Unit-тесты без PostgreSQL | бизнес-правила отделены от инфраструктуры | `make test-unit` | `ci.yml` → `backend` |
| Правила зависимостей | модульность не деградирует | `make test-unit` (пакет `archtest`) | `ci.yml` → `backend` |
| Модуль собирается вне монолита | «extraction-ready» — проверяемый факт, а не заявление | `make test-extract` | `ci.yml` → `extraction` |
| Рецепт конструктора даёт рабочий проект | из рецепта получается проект, который собирается и запускается сам | `make test-constructor` | `ci.yml` → `constructor` |
| Миграции на пустой БД | схема создаётся с нуля | `make migrate` | `ci.yml` → `backend` |
| Повторный запуск миграций | миграции идемпотентны | `make migrate` дважды | `ci.yml` → `backend` |
| Обновление существующей БД | продукт обновляем, а не только устанавливаем | `make migrate` на базе предыдущей версии | `portability.yml` → `upgrade-path` |
| OpenAPI не разошёлся с кодом | документация API генерируема и актуальна | `make openapi-check` | `ci.yml` → `backend` |
| Контрактные тесты API | маршрут без права/схемы ловится | `make test-unit` | `ci.yml` → `backend` |
| Интеграционные тесты | транзакции, RBAC, изоляция на реальной БД | `make test-integration` | `ci.yml` → `backend` |
| Tenant isolation и RBAC | пользователи не получают чужие данные | `make test-integration` | `ci.yml` → `backend` |
| Compose smoke test | сервисы действительно взаимодействуют | `./scripts/smoke-test.sh` | `portability.yml` → `compose-smoke` |
| Backup → restore → smoke | данные восстанавливаются, а не только копируются | `make backup` → `make restore` → `make smoke-test` | `portability.yml` → `backup-restore` |
| E2E в Chromium | основные сценарии работают в браузере | `make test-e2e` | `ci.yml` → `e2e` |
| Конфигурация без секретов | проект не зависит от случайных локальных ключей | `./scripts/check-env.sh` | `portability.yml` → `config-without-secrets` |
| Документация полна и связана | документы существуют, ссылки живые, спецификации модулей заполнены | `make docs-check` | `portability.yml` → `docs` |
| Зависимости и образы без известных уязвимостей | нет известного вредоносного кода в поставке | `govulncheck`, `gosec`, `gitleaks` | `ci.yml` → `security` |
| Многократная репликация корректна | несколько API не ломают инварианты | `./scripts/multi-replica-verify.sh` | ручной прогон, описано в `deploy/` |
| Проверка хоста перед развёртыванием | окружение пригодно, и это видно до запуска | `make doctor` | локально |

## Как читать эту матрицу

- **Зелёный CI — не доказательство переносимости целиком**, а доказательство
  перечисленных утверждений. Неперечисленное не проверено.
- Проверки уровней **A–B** (код, артефакты) идут без БД; **C** требует PostgreSQL;
  **D** — сборку образов; **E** — чистое развёртывание. См. [BUILD.md](../../BUILD.md).
- Изменение поведения = изменение строки матрицы. Новая гарантия без строки — не
  гарантия.

## Сознательно не проверяется автоматически

- Производительность и нагрузка.
- Восстановление после потери узла целиком (только данные, не инфраструктура).
- Качество ответов AI-провайдера.
- Совместимость с MySQL/MariaDB — не поддерживается ([ADR 0008](../adr/0008-mysql-mariadb-datastore-blockers.md)).
