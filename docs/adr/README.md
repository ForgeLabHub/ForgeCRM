# Architecture Decision Records

Решения, которые дорого менять: каждое фиксирует контекст, альтернативы и условие
пересмотра. Формат: `NNNN-короткое-имя.md`.

| # | Решение | Что определяет |
| --- | --- | --- |
| [0001](0001-hybrid-architecture.md) | Гибридная архитектура, модульный монолит | границы модулей и порты |
| [0002](0002-service-extraction-triggers.md) | Триггеры выделения сервиса | когда модуль отделяют, а когда нет |
| [0003](0003-multi-replica-safety-detour.md) | Безопасность нескольких реплик | что требует внешнего Redis |
| [0004](0004-webhook-retry-budget-and-replay.md) | Бюджет повторов и replay вебхуков | гарантии доставки |
| [0005](0005-hitl-agent-execution-model.md) | Human-in-the-loop для агентов | кто подтверждает деструктивные действия |
| [0006](0006-prompt-architecture-and-local-inference.md) | Архитектура промптов и локальный вывод | что подаётся модели и почему |
| [0007](0007-workflow-automation-engine.md) | Движок автоматизации | почему декларативные шаги, а не код |
| [0008](0008-mysql-mariadb-datastore-blockers.md) | Отказ от MySQL/MariaDB | границы поддерживаемых СУБД |

## Шаблон нового ADR

```
# NNNN. Заголовок решения
## Контекст
## Решение
## Альтернативы
## Последствия
## Условия пересмотра
```

ADR не переписывается после принятия: изменение решения оформляется новым ADR,
старый помечается `Superseded by NNNN`.
