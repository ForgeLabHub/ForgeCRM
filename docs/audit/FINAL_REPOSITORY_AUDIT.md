### 2.2 Что показал анализ

**`delivery` — полностью интегрирована.** Дерево `delivery` совпадает с деревом
её squash-merge коммита `5584b89` (`git diff` пуст), а `5584b89` — предок `main`
(PR #45). Значит, всё содержимое ветки уже в `main` в виде единого коммита.
«Уникальные» строки `git cherry` — это старые версии, которые `main` перерос:
`x/crypto v0.58.0` и `edwards25519 v1.1.0` (в `main` они обновлены по CVE),
устаревший шаг установки gosec, отсутствие миграции `0031_worker_heartbeats`.
Двухточечный диф `main..delivery` = `+97 / −3063`: ветка далеко позади.

**`feat/frontend-redesign` — в основном интегрирована.** Отзывчивый редизайн,
полное RU-покрытие и унифицированные диалоги уже в `main` (squash-merge #45).
Уникальный остаток — альтернативная реализация: рефакторинг на
`components/ds/*`, `navigation.ts`, `styles/design-system.css`, заметка AGENTS.md
о порядке CSS-импортов. Это не отдельная функциональность, а другой способ
сделать то же самое; `main` без неё полностью проходит (260 frontend-тестов,
lint/typecheck/build).

**`arena` — устаревшая и регрессирующая ветка с одним ценным коммитом.**
База — `6484a50` (до финализации релиза). Ветка **удаляет** артефакты релиза,
которых в ней нет:

| `backend/internal/jobs/heartbeat.go` |
| `backend/internal/migrations/0031_worker_heartbeats.up.sql` / `.down.sql` |
| `docs/performance/baseline.md` |

| `backend/internal/testsupport/trgm_indexes_test.go` |
| `backend/internal/api/bench_test.go` |

Слияние вслепую откатило бы финализацию. CI на голове `36e74d8` — **красный**:
job «Visual regression (baselines on Linux)» падает (расхождения 2–6% на
login/dashboard), а в логе миграции применяются только до `v30` — прямое
подтверждение, что ветка отстала от релиза (`v31`). Заявленный в описании PR #48
«Merge delivery history using the ours strategy» — история без изменений файлов.

**Ценный остаток `arena`:** независимый коммит `36e74d8` «Add MCP batch handling
and configurable cookie attributes» — пакетная обработка JSON-RPC (до 100
сообщений), приоритет `X-API-Key`, настраиваемые атрибуты session-cookie
(`SameSite`, `Partitioned`). В `main` этого нет (`HandleMessage`/`mcpToken` не
найдены).

### 4.2 blitz.cloud — ⚠️ NOT VERIFIED

Приложение развёрнуто по адресу `https://forgecrm.forgecrm.blitz.cloud/`, но
отвечает `503 {"status":"asleep"}` на `/health`, `/ready` и `/`: это состояние
сна бесплатного тарифа. Панель сообщает, что программно разбудить приложение
нельзя — только открытием в браузере (или Pro). Открытие в браузере и серия
запросов в течение нескольких минут приложение не разбудили (возможно, оно
остановлено и требует **Start** из панели).

Поэтому фактическая версия и состояние **живого** приложения не подтверждены —
`NOT VERIFIED`. Проверена только воспроизводимость развёртывания (§4.1) и job CI
«Blitz Cloud deployment (root image, clean database)» (✅ на `main`).

**Действие владельца:** открыть приложение на `dashboard.blitz.cloud`, нажать
**Start**, затем сверить `/ready` (`commit`/`version`) с `main`. Документация по
развёртыванию — [blitz-cloud.md](../deployment/blitz-cloud.md).
