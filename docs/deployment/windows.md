# Развёртывание ForgeCRM на Windows

Это руководство поднимает работающий ForgeCRM (API + фоновый воркер +
веб-интерфейс + PostgreSQL) на Windows через Docker Desktop. Отдельно описано,
как запустить только API и веб-интерфейс без контейнеров, если нужен быстрый цикл
разработки.

Всё, что здесь описано, можно запускать и останавливать командами `forge.bat` —
той же оболочкой, что и на Unix (`forge.sh`), с теми же командами и той же
логикой. Ниже — что именно делает каждая команда, чтобы при сбое было понятно,
где смотреть.

## Что нужно заранее

| Компонент | Версия | Проверка |
| --- | --- | --- |
| Docker Desktop | актуальная, с включённым WSL 2 или Hyper-V | `docker version` |
| Git for Windows | любая | `git --version` |
| Go | 1.26.10 (совпадает с `backend/go.mod`) | `go version` |
| Node.js | 22 (совпадает с `.github/workflows/ci.yml`) | `node --version` |

Docker Desktop должен быть запущен до первой команды: `forge.bat doctor` сообщит
об этом явно, а не через таймаут.

Go и Node.js нужны только для запуска без контейнеров и для `make`-целей
(`test`, `lint`, `build`, `verify`). Для контейнерного стека достаточно Docker
Desktop и Git.

## Путь 1: стек в контейнерах (рекомендуется)

Это тот же стек, что описан в [README.md](README.md): `postgres`, `api`,
`worker` и опциональный `nginx`. API и воркер используют один образ; отличается
только точка входа. Очередь заданий, outbox и доставка событий опираются на
PostgreSQL — Redis и брокер сообщений не требуются.

```bat
forge.bat env init          :: создать .env из .env.example, заглушки секретов заменяются случайными
forge.bat env check         :: сверить .env с .env.example; пустые и «примерные» секреты — ошибка
forge.bat doctor            :: проверить Docker, .env, занятость порта
forge.bat prod              :: docker compose up -d --build
forge.bat status            :: что запущено и отвечает ли порт
forge.bat admin you@example.com
forge.bat smoke             :: GET /health по HTTP
```

`forge.bat env init` создаёт `.env` с правами, не перезаписывая существующий
файл (прежний сохраняется как `.env.bak`), и подставляет случайные значения
вместо заглушек вроде `change-me`. Ни один секрет не попадает в Git: `doctor`
проверяет, что `.env` указан в `.gitignore`.

### Создание первого администратора

Пароль передаётся через окружение, чтобы не осесть в истории команд и в списке
процессов:

```bat
set FORGECRM_BOOTSTRAP_PASSWORD=<сильный пароль>
forge.bat admin you@example.com
```

Команда выполняется в одноразовом контейнере (`docker compose run --rm
--no-deps`), поэтому не мешает уже запущенному API. Повторный запуск с тем же
адресом не создаёт второго администратора.

### Миграции

API применяет ожидающие миграции при старте только когда
`FORGECRM_MIGRATE_ON_START=true`; по умолчанию флаг выключен. Воркер ждёт
готовности API, поэтому две версии с разными наборами миграций не запускаются
против одной базы одновременно.

```bat
forge.bat migrate           :: применить ожидающие миграции
forge.bat db migrate        :: то же самое
```

### Остановка и удаление

```bat
forge.bat stop              :: остановить процессы, запущенные forge.bat start
forge.bat docker down       :: остановить контейнеры; данные (volume pgdata) сохраняются
```

`docker down` данные не удаляет. Удаление томов — только явное
`docker compose down -v` или подтверждение в `docker reset`, и это осознанное
действие: оно уничтожает базу.

### Резервная копия и восстановление

```bat
forge.bat db backup                     :: дамп базы
forge.bat db restore <путь-к-дампу>     :: восстановление из дампа
```

Порядок и проверка восстановления описаны в
[../database/backup-restore.md](../database/backup-restore.md). Резервную копию,
восстановление которой не проверяли, нельзя считать резервной копией.

## Путь 2: только API и веб-интерфейс, без контейнеров

Для быстрого цикла разработки нужны Go, Node.js и доступная база PostgreSQL
(можно поднять только её: `docker compose up -d postgres`, раскомментировав порт
в `docker-compose.yml`).

```bat
forge.bat install           :: зависимости backend и frontend
forge.bat api               :: cd backend ^&^& go run ./cmd/forgecrm-api  (порт 8080)
forge.bat web               :: cd frontend ^&^& npm run dev               (порт 5173)
forge.bat dev               :: база + API + фронтенд, затем smoke
forge.bat start             :: API и (если есть node_modules) фронтенд, открыть браузер
forge.bat status
forge.bat stop
```

По умолчанию API слушает `http://localhost:8080`; `forge.bat start` открывает
браузер на этот адрес. Порт переопределяется переменной окружения или `.env`
(приоритет: **окружение → `.env` → встроенное значение**), поэтому
`set PORT=9000 && forge.bat start` работает независимо от файла.

### Ограничение `cmd.exe`

Значения в `.env`, содержащие `%` или `!`, парсером `forge.bat` не
поддерживаются — это ограничение `cmd.exe`, а не логики. Секреты, которые вы
генерируете командой `forge.bat env init`, состоят из букв и цифр, поэтому
под ограничение не попадают. Если значение обязано содержать эти символы, задайте
его переменной окружения или запускайте через `forge.sh` в WSL.

## Проверки

```bat
forge.bat test              :: unit-тесты backend и frontend, без базы
forge.bat lint              :: форматирование, go vet
forge.bat verify            :: lint + test + docs-check
forge.bat smoke             :: GET /health живого инстанса
```

`test`, `lint`, `build` и `verify` запускаются в окружении **без** переменных из
`.env`: иначе локальные проверки вели бы себя иначе, чем CI.

## Если что-то не работает

| Симптом | Причина и что делать |
| --- | --- |
| `doctor` сообщает, что Docker не найден | Docker Desktop не запущен. Запустите его и повторите. |
| `doctor` сообщает, что порт занят | Другой процесс слушает `PORT`. Остановите его или задайте другой `PORT`. |
| `env check` находит «примерные» секреты | `.env` создан копированием, а не `env init`. Выполните `forge.bat env init --force`. |
| `smoke` не отвечает, а `status` показывает процесс | API ещё применяет миграции. Подождите и повторите; `forge.bat logs api` покажет прогресс. |
| Воркер перезапускается | Проверьте `forge.bat logs` — вероятно, база недоступна или API ещё не поднялся. Воркер ждёт готовности API. |
