# T2 — Telegram Assistant: аудит, карта архитектуры и план

Статус: **T2.1 (аудит) завершён, ожидает утверждения плана.** Реализация T2.2–T2.8 не начиналась.

Область: существующая Telegram-инфраструктура ForgeCRM. Цель T2 — довести её до
полноценного интерфейса управления CRM, не переписывая работающие механизмы и не
создавая второй системы авторизации.

## 1. Резюме

Аудит показал, что Telegram-бот **уже реализован существенно глубже**, чем
предполагалось в постановке. Уже существуют: локализация RU/EN с расширяемым
каталогом, onboarding, inline-меню, справка, команды задач/профиля/уведомлений,
дедупликация update, шифрование отложенных ответов, привязка аккаунта по
одноразовым кодам, доставка через существующую очередь jobs с retry/backoff,
проверка RBAC/tenant/consent перед отправкой и PNG-карточки задач.

Поэтому T2 — это **не написание бота заново, а закрытие подтверждённых пробелов**.
Основные пробелы: (1) карточки уведомлений рендерятся не на выбранном в боте
языке; (2) из бота нельзя отвязать аккаунт; (3) кнопки уведомлений нет в меню;
(4) нет пользовательских настроек типов уведомлений; (5) документация отстала от
кода; (6) часть путей (legacy `HandleCommand`) не покрыта и вводит в заблуждение.

Уже соблюдены требуемые ограничения: используется **существующая** модель
пользователей/RBAC (`rbac.Principal`, `ResolveUser`), **существующая** очередь
jobs (отдельная таблица — только долговечный журнал дедупликации, не очередь),
**существующий** consent-гейт. Второй системы авторизации нет.

## 4. Подтверждённые дефекты (с доказательствами)

1. **Язык карточек уведомлений игнорирует выбор в боте.** Worker
   (`cmd/forgecrm-worker/telegram.go`) выбирает `u.locale` из `users`, а `users.locale`
   не устанавливается ни одним путём (в коде нет `UPDATE users ... locale`); язык
   пользователя хранится в `telegram_user_settings.locale`. Итог: пользователь
   выбрал русский, а карточки приходят на английском. Ответы бота при этом
   локализованы корректно — расхождение только в уведомлениях.
2. **Из бота нельзя отвязать аккаунт.** `/unlink` реализован только в legacy
   `HandleCommand`, который в webhook-диспетчере не вызывается; кнопки отвязки в
   меню нет. Отвязка доступна лишь через REST/frontend.
3. **Кнопка «Уведомления» отсутствует в меню**, хотя callback `menu:notifications`
   и команда `/notifications` работают.
4. **Нет пользовательских настроек типов уведомлений** (только общий consent по
   каналу/цели). Пользователь не может отключить отдельные типы.
5. **Документация отстала.** `docs/telegram/PHASE2_STATUS.md` описывает состояние
   до локализации/меню; в нём перечислен неполный список команд и неверно указана
   ветка.
6. **Дублирующий путь.** `TelegramService.HandleCommand` — вторая реализация
   диспетчера с захардкоженным EN-текстом и командой `/unlink`, не используемая
   production-путём, но покрытая тестами. Создаёт риск расхождения.

## 5. План T2.2–T2.8 (после утверждения)

Каждый этап — отдельная проверяемая порция изменений в `main` с логическим
коммитом и прогоном релевантных тестов.

- **T2.2 — `/start`, привязка, onboarding.** Проверить и при необходимости
  дополнить: первый запуск (язык → возможности → инструкция привязки → меню);
  для привязанного — сразу меню. Убедиться, что onboarding не повторяется.
- **T2.3 — язык RU/EN, расширяемая локализация.** Устранить дефект №1 (карточки
  читают язык из `telegram_user_settings` с fallback на `users.locale`/EN).
  Добавить тест каталогов на полноту для всех локалей. Добавить ключи для новых
  строк меню/отвязки/настроек.
- **T2.4 — inline-меню, `/help`, навигация.** Добавить кнопки «Уведомления» и
  «Отвязать»; синхронизировать `/help` со списком команд; сохранить текущую
  навигацию задач.
- **T2.5 — `/tasks`, `/profile`, `/notifications`.** Убедиться, что `/profile`
  показывает язык/организацию; `/notifications` — последние уведомления; добавить
  `/unlink` в webhook-диспетчер с подтверждением (опасная мутация).
- **T2.6 — RBAC и tenant isolation.** Тесты: команды без прав, чужой организацией,
  отвязка, доступ к задачам другого сотрудника — все должны отклоняться; проверка,
  что скрытие кнопок не является единственной защитой.
- **T2.7 — уведомления, retry, idempotency, dedup.** Настройки типов уведомлений
  (assignment / due_changed / overdue / completed) с хранением и учётом в worker;
  локализация карточек; сохранение dedup/retry; тесты на отключённый тип.
- **T2.8 — полный интеграционный аудит.** Прогон unit/integration/race, проверка
  миграций на чистой БД, обновление документации, финальный отчёт.

## 6. Границы

- Никаких обходов RBAC/tenant isolation; никаких дублирующих таблиц/очередей.
- Production, секреты, DNS и конфигурация развёртывания не изменяются.
- Mini App и рабочие пространства — вне T2 (отдельные фазы).
- Существующие baseline-тесты не ослабляются ради зелёного CI.

## Статус реализации (T2)

Решения утверждены, реализация выполнена в `main` отдельными коммитами.

- **T2.3 (язык карточек).** Worker строит карточку уведомления по языку `telegram_user_settings.locale` → `users.locale` → `en`. Язык бота не переписывает глобальную локаль CRM. Каталог `telegramtext` расширен; `TestCatalogsAreComplete` удерживает паритет RU/EN.
- **T2.4 (меню и справка).** Inline-меню дополнено кнопками «Уведомления», «Настройки», «Отвязать»; `/help` перечисляет новые команды.
- **T2.5 (`/settings`, `/unlink`).** `/settings` показывает типы уведомлений и переключает их callback-ом; `/unlink` требует подтверждения и вызывает существующий `Unlink`.
- **T2.7 (типы уведомлений).** Новая таблица `telegram_notification_preferences` (миграция `0036`) по Telegram-аккаунту; отсутствие строки = включено; глобальный consent-гейт обязателен. Отключённый тип пропускается в worker с исходом `muted`.
- **T2.6 (RBAC/tenant).** Все новые пути идут через `resolveLinked`/`ResolveUser`; тесты проверяют отказ для непривязанного аккаунта и после отвязки.

Проверки: unit (`api`, `notify`, `telegramtext`), интеграционные Telegram-тесты (`internal/api`, `internal/testsupport`, `cmd/forgecrm-worker`) на disposable PostgreSQL; миграции применяются на чистой БД.
