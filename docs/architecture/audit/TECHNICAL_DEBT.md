## TD-1. `crm` импортирует `httpx` (нарушение слоистости)

- **Место:** `backend/internal/crm/*.go` — использование `httpx.APIError`,
  `httpx.Pagination`, `httpx.SortSpec`.
- **Проблема:** тип доменной ошибки живёт в пакете, названном по HTTP. Ядро
  зависит от транспортного слоя.
- **Серьёзность:** Низко (однонаправленно, цикла нет).
- **Последствия:** при выделении `crm` в отдельный сервис тянет за собой
  HTTP-слой; затрудняет замену транспорта.
- **Исправление:** ввести `internal/crm/errors.go` (или `internal/domainerr`) с
  доменными типами ошибок и пагинации; маппинг в HTTP — в `api`/`httpx`.
- **Зависимости:** `httpx`, `api`, `crm`; контракт OpenAPI не меняется.
- **Проверка:** `TestCoreDoesNotImportCompositionOrHTTP` должен оставаться
  зелёным без исключения `httpx` из списка разрешённых; `go test ./internal/crm/...`.
- **Статус:** Отложено (свойство закреплено тестом).

## TD-2. Общая схема БД — нет явного владения данными по модулям

- **Место:** `backend/internal/migrations/*.sql` (83 таблицы, одна схема).
- **Проблема:** все модули читают/пишут одну схему; прямые SQL-обращения к чужим
  таблицам не запрещены технически (только конвенцией).
- **Серьёзность:** Средне.
- **Последствия:** это **блокер для полноценных микросервисов**: сервисы не могут
  владеть своими данными без разделения схем. Для текущего модульного монолита —
  приемлемо (ADR 0001 требует одной транзакции).
- **Исправление:** для микросервисной ветки — выделить схему на контекст
  (`CREATE SCHEMA`), запретить межсхемные запросы, ввести read models/события.
  Для `main` — задокументировать правило владения таблицами.
- **Зависимости:** все прикладные сервисы; миграции; `internal/database`.
- **Проверка:** тест-хранитель на граф обращений (аналогично archtest), который
  падает, когда пакет X выполняет SQL по таблице, закреплённой за пакетом Y.
- **Статус:** Открыто (архитектурное; требует решения владельца, §6 PROJECT_AUDIT).

## TD-3. Нет метаданных переносимости на модуль (`manifest.yaml`, `MODULE.md`)

- **Место:** `backend/internal/<pkg>` — нет `manifest.yaml`/`MODULE.md`.
- **Проблема:** 36 модулей **фактически** переносимы (доказано харнессом), но
  формального манифеста (входы/выходы, env, миграции, события, API) и
  инструкции по переносу нет.
- **Серьёзность:** Средне (главный пробел Этапа E).
- **Последствия:** переносимый модуль нельзя обнаружить/понять без чтения кода;
  нельзя автоматически проверить контракт переноса.
- **Исправление:** сгенерировать/написать `manifest.yaml` + `MODULE.md` для
  извлекаемых модулей, начав с ядра (`crm`, `rbac`, `jobs`, `outbox`, `authn`,
  `ai`, `notify`, `events`, `storage`, `analytics`).
- **Зависимости:** `scripts/extract-test/modules.txt`, `internal/constructor`.
- **Проверка:** новый гейт `scripts/module-docs-check.sh`, который падает, если
  модуль из `modules.txt` не имеет `manifest.yaml` с обязательными полями.
- **Статус:** Открыто — **основная работа Этапа E**.

## TD-4. Инфраструктурные адаптеры покрыты неравномерно

- **Место:** `internal/ai/ai.go` (`Provider` — есть), `internal/objectstore`
  (`ObjectStore` — есть), `internal/events/delivery.go` (`Poster` — есть);
  но `internal/notify/email.go` и `internal/notify/telegram.go` — конкретные
  структуры без интерфейса провайдера.
- **Проблема:** замена почтового/Telegram-провайдера требует правки вызывающего кода.
- **Серьёзность:** Низко-Средне.
- **Последствия:** ограничивает Этап F («заменяемость компонентов»).
- **Исправление:** ввести узкие интерфейсы `notify.EmailSender`/`notify.Sender`
  и адаптеры (SMTP, внешний провайдер) + contract-тесты на одинаковое поведение.
- **Зависимости:** `notify`, `consent`, `wiring`, `jobs`.
- **Проверка:** contract-тест, прогоняющий два адаптера через один набор кейсов.
- **Статус:** Открыто.

## TD-5. Нет версии у публичных интерфейсов модулей

- **Место:** Go-пакеты не несут версию; версия есть у OpenAPI (пути `/api/v1`) и
  у событий (`outbox.schema_version`).
- **Проблема:** «версионирование публичных интерфейсов» из Этапа B выполнено
  частично.
- **Серьёзность:** Низко.
- **Исправление:** отражать версию модуля в `manifest.yaml`; для событий —
  политика совместимости в `EVENT_CATALOG.md`.
- **Проверка:** гейт `module-docs-check.sh` (TD-3).
- **Статус:** Открыто.

## TD-6. 40 предупреждений ESLint (fast-refresh)

- **Место:** `frontend/src/**` — файлы, экспортирующие и компонент, и константу
  (напр. `WorkspaceProvider.tsx`, `AccountThemeProvider.tsx`).
- **Проблема:** предупреждение `react-refresh/only-export-components`.
- **Серьёзность:** Низко (0 ошибок; lint-гейт зелёный).
- **Последствия:** потенциально менее стабильный HMR в dev.
- **Исправление:** вынести константы/хуки в отдельные файлы.
- **Проверка:** `npm run lint` без предупреждений.
- **Статус:** Отложено (низкий приоритет; не блокирует CI).

## TD-8. Путь Go-модуля не совпадает с владельцем репозитория

- **Место:** `backend/go.mod` — `module github.com/geff1778/forgecrm`; remote —
  `github.com/ForgeLabHub/ForgeCRM`. Упоминание старого владельца в тексте есть
  только в историческом `docs/PROJECT_AUDIT.md` (не переписывается намеренно).
- **Проблема:** путь модуля указывает на другого владельца, чем фактический
  репозиторий.
- **Серьёзность:** Низко (не влияет на сборку и CI; модуль не публикуется).
- **Последствия:** `go get`/публикация модуля указывали бы не туда; для локальной
  сборки и CI безразлично.
- **Исправление:** при необходимости — переименовать путь модуля и обновить все
  импорты (механическая, но широкая правка). **Не делать молча** — это отдельное
  решение владельца.
- **Проверка:** `head -1 backend/go.mod`; `go build ./...` после переименования.
- **Статус:** Открыто (низкий приоритет; вне объёма текущей программы).

## TD-9. Нет локального IdP (Keycloak) для E2E OIDC

  контейнера для E2E нет.
- **Серьёзность:** Низко.
- **Исправление:** добавить профиль compose с локальным IdP.
- **Проверка:** E2E-сценарий SSO в CI.
- **Статус:** Открыто (уже в «Следующих приоритетах» исторического аудита).

## TD-10. Telegram Mini App не реализован

- **Место:** нет кода Mini App (ни backend, ни frontend).
- **Проблема:** требование «довести Telegram до полноценного продукта» включает

- **Исправление:** оценивать как отдельный следующий этап; не выдавать

- **Проверка:** появление каталога `frontend/src/telegram-miniapp` + маршрут.
- **Статус:** Открыто (вне объёма текущей программы).
