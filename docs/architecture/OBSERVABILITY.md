# Наблюдаемость ForgeCRM

> Соответствует коду на `main` @ `3424b3e`.

## Логи

- `internal/logging`: `slog`, request ID и correlation ID, центральное
  **маскирование секретов**. Один формат для API и worker.

## Метрики

- `internal/metrics`: экспозиция в формате Prometheus text 0.0.4.
- Без внешней клиентской библиотеки; значения читаются из БД, поэтому корректны
  при нескольких репликах.
- Порядок детерминирован (метрики по имени, сэмплы по набору меток) — тело
  скрейпа можно диффить и тестировать.

## Трассировка

- `internal/tracectx`: correlation ID протягивается из запроса в события и логи.
- В микросервисной ветке тот же ID пойдёт через границы сервисов.

## Аудит

- `internal/audit`: append-only журнал + верификатор целостности (ADR 0012).
- Записываются входы, отказы авторизации, опасные операции, dead-letter вебхуков.

## Здоровье

| Endpoint | Смысл |
|---|---|
| `/health` | процесс жив |
| `/ready` | зависимости готовы (БД) |

## Диагностика

- `internal/api/system_handlers.go` — статус подсистем (ai/telegram/email/storage).
- `scripts/doctor.sh`, `scripts/forge-check.sh` — локальная диагностика.

## Что смотреть при сбое

1. `/ready` — готова ли БД.
2. Логи по correlation ID запроса.
3. Метрики очереди/outbox.
4. Аудит — отказы авторизации и dead-letter.
