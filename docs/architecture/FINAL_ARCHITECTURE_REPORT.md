## 2. Найденные проблемы

Полный разбор — `audit/TECHNICAL_DEBT.md` (TD-1…TD-10) и `audit/SECURITY_AUDIT.md`
(S-1…S-4). Критических нет. Главные:

1. **Архитектурное противоречие** (не дефект кода): требование «`main` =
   микросервисы» + «ветка `monolith`» противоречит ADR 0001/0002 и факту, что
   `main` уже модульный монолит. → ADR 0013.
2. **TD-2** — общая схема БД; блокер для микросервисов.
3. **TD-3** — у модулей не было метаданных переносимости.
4. Прочее — низкой серьёзности (слоистость `crm→httpx`, ESLint-предупреждения,
   устаревший статус ROADMAP, несоответствие пути Go-модуля владельцу репо).

- Этап C (микросервисы) — не начат (ADR 0013).
- Ветка `monolith` — не создана (была бы дублем).
- TD-2 (разделение схем), TD-4 (адаптеры notify), TD-9 (локальный IdP), TD-10
  (Mini App) — открыты.
- Метаданные: покрыты все 36; часть полей (tables/migrations) заполнена
  консервативно и уточняется при разделении схем.

## 16. Риски

| Риск | Влияние | Митигация |
|---|---|---|
| Микросервисы без разделения данных | распределённый монолит | ADR 0013 требует разделения схем первым |
| Регрессии при будущем распиле | нарушение транзакций | триггеры ADR 0002, пилот на 1 сервисе |
| Дрейф метаданных | документация устареет | генератор + гейт `module-docs-check.sh` |

## 17. Сравнение Microservices и Modular Monolith

| Свойство | Модульный монолит (`main`, реализовано) | Микросервисы (цель) |
|---|---|---|
| Транзакции | локальные, атомарные | распределённые (саги) |
| Границы | направление зависимостей (тесты) | сеть + контракты |
| Деплой | один артефакт | независимый |
| Изоляция ресурсов | грубая (API/worker) | полная |
| Стоимость ошибки | влияет на всё | изолирована |
| Готовность | **есть** | **нет** |
