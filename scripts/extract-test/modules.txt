# Modules the extraction harness proves independent of the ForgeCRM monolith.
#
# One module per line, below the blank line. Each has a
# scripts/extract-test/<module>/setup.sh that copies it into a clean Go module and
# builds, tests and runs it there.
#
# A module is listed here only when its extraction actually passes. Listing a
# module that does not extract would make the harness lie, which is worse than not
# listing it.
#
# netguard      the SSRF guard; standard library only, the leaf everything else may depend on
# analytics     money, ratio and scenario maths; no dependency at all
# ratelimit     fixed-window limiter with in-memory and Redis stores
# objectstore   the object-storage layer, extracted from internal/storage in this slice
# secrets       password hashing, tokens and the AES-GCM keyring; x/crypto only
# logging       structured logging with central secret redaction; standard library only
# httpx         the HTTP layer: error envelope, JSON writers, middleware, client address
# safe          untrusted-archive extraction (internal/importx/safe); a leaf
# parsers       tabular source parsing (internal/importx/parsers); a leaf
# database      the PostgreSQL pool and transaction helper; a leaf
# rbac          permission catalog, principal and resolution service
# audit         append-only action trail and security events
# outbox        transactional outbox with the event vocabulary
# retention     data-retention engine: policy catalog, dry-run default, opt-in delete
# agent         human-in-the-loop proposal queue with a signed approval
# jobs          the queue: enqueue, claim, complete/fail, bounded retry backoff
# crm           the domain service: accounts, contacts, deals, tasks, tickets, activities
# storage       object-store application layer: documents, entity attachment, reconcile
# integrations  Integration Hub: adapter lifecycle, SSRF guard, secret handoff, run log
# config        the environment loader: every FORGECRM_* variable, defaults, validation
# workflow      the automation engine: step document, cron, template catalog, export/import
# events        the inbound webhook gateway: signature, timestamp window, dead-letter
# migratex      the cross-database migration service: source adapters, reconciliation
# simulate      the Simulation Lab: scenario catalog and preview over the analytics core
# forecast      the revenue forecast: method catalog and accuracy
# risk          the Risk scan: thresholds, scan and signal reconciliation
# notify        outbound transports: email and Telegram, off when unconfigured
# ai            the contextual AI layer: prompt assembly, tool risk tiers, MCP protocol
# importx       the Import Center: format detection, field catalog, parser leaves
